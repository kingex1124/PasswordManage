## 2. 專案目標與定位

### 2.1 目標
建立一個「純靜態網站」的帳密管理工具，提供：
1. 帳密資料維護（新增、編輯、刪除）
2. 匯出為 JSON 並對整包資料加密
3. 匯入加密 JSON 並以密碼解密
4. 所有密碼欄位預設遮罩，使用眼睛圖示可切換明文
5. 依「類別 / 種類 / 帳號關鍵字」查詢與排序
6. 離線可用（PWA）

### 2.2 邊界
- **In Scope**
  - 前端單頁應用（可多模組，但不可依賴後端 API）
  - 本機資料操作、檔案匯入/匯出
  - 使用 `crypto-js-lib` 進行加解密
  - PWA（離線可用、可安裝）
- **Out of Scope（本版不做）**
  - 雲端同步、多人協作
  - 帳號登入系統
  - 後端資料庫
  - 2FA、硬體金鑰整合

## 3. 技術與環境約束
1. 架構：純前端、可部署於 GitHub Pages/靜態主機。
2. 加密：必須使用 `crypto-js-lib`。
3. 瀏覽器：需支援 Web Crypto API（不額外訂定最低版本，採主流現代瀏覽器）。
4. 執行環境：
   - 開發可用 localhost
   - 正式環境需 HTTPS
5. 不可將明文密碼上傳到任何外部服務。

## 4. 名詞定義
- 類別（Category）：高層分類，例如「信箱」。
- 種類（Type）：平台或服務，例如「Yahoo 平台」。
- 帳號（Account）：登入帳號識別值。
- 密碼歷程（Password History）：同一帳號可有多組密碼，每次更新須保留歷史與日期。
- 存檔密碼（Archive Password）：用於加密/解密匯出檔案的密碼。

## 5. 使用者故事（User Stories）
1. 作為使用者，我希望新增類別/種類/帳號/密碼資料，方便集中管理。
2. 作為使用者，我希望每次改密碼都保留舊密碼與日期，便於追溯。
3. 作為使用者，我希望按下存檔可匯出加密 JSON，避免明文外洩。
4. 作為使用者，我希望重新開啟網站時可匯入舊檔並輸入密碼解密。
5. 作為使用者，我希望可以變更存檔密碼，再次匯出時採用新密碼。
6. 作為使用者，我希望所有密碼預設遮罩，只有手動點眼睛才顯示。
7. 作為使用者，我希望可依類別/種類/帳號關鍵字快速查詢，並保留篩選條件進行排序。
8. 作為使用者，我希望可離線使用。

## 6. 功能需求（Functional Requirements）

### FR-001 資料新增
- 系統須允許新增一筆帳密資料，欄位包含：
  - 類別（必填，來源為「類別主檔」下拉選單）
  - 種類（必填，來源為「種類主檔」下拉選單）
  - 帳號（必填）
  - 密碼（至少 1 筆，必填）
  - 備註（選填，無長度上限）
- 新增時密碼歷程須自動建立一筆：
  - `password`
  - `changedAt`（預設為建立當下時間，可手動調整）

### FR-002 同類別/種類多筆資料
- 同一類別可有多個種類。
- 同一種類可有多個帳號。
- 系統以資料 `id` 區分，不以「類別+種類」限制唯一。

### FR-003 密碼歷程管理
- 同一帳號可新增多筆密碼歷程。
- 密碼歷程可刪除，且不需保留刪除稽核紀錄。
- 密碼內容允許空白字元、特殊符號與 Unicode。
- 歷程筆數不設上限。
- 顯示順序為 `changedAt DESC`（精度至時分秒；同日可多筆）。

### FR-004 密碼遮罩與顯示切換
- 所有密碼欄位預設顯示遮罩（例如 `••••••`）。
- 每個密碼列旁須有眼睛圖示切換顯示/隱藏。
- 僅逐筆切換，不提供全域顯示/隱藏。
- 明文顯示後需於 60 秒自動恢復遮罩。

### FR-005 匯出加密檔案
- 使用者按「存檔」時：
  1. 輸入存檔密碼（不限制最小長度與複雜度）
  2. 系統將完整資料序列化為 JSON 明文
  3. 使用 `crypto-js-lib` 加密後輸出檔案
- 若目前已有「已匯入或已指定」的目標檔案控制代碼，存檔時應直接覆蓋原檔。
- 若瀏覽器不支援直接覆蓋原檔能力，退回一般下載流程（另存新檔）。
- 匯出檔案格式：`.json`
- 匯出檔名規則：`password-manage-YYYYMMDD-HHmmss.json`
- 檔案內容不得包含可直接讀取的帳號密碼明文。
- 不額外寫入 `appName`、`createdBy` 等 metadata。

### FR-006 匯入加密檔案
- 使用者可選擇先前匯出的 `.json` 檔案。
- 匯入時須輸入對應存檔密碼。
- 匯入策略固定為**覆蓋全部**（以檔案內容取代目前畫面資料）。
- 解密成功後載入資料到畫面。
- 解密失敗時：
  - 不覆蓋當前資料
  - 顯示錯誤訊息
  - 觸發 5 秒延遲後才可再次嘗試解密

### FR-007 編輯存檔密碼
- 匯入成功後，介面需提供「修改存檔密碼」欄位。
- 變更後僅在下一次匯出時生效（以新密碼重新加密檔案）。
- 允許於記憶體暫存存檔密碼至分頁關閉。
- 可回寫原檔：若已取得原檔寫入權限，下一次存檔預設覆蓋原檔。

### FR-008 查詢與排序
- 提供資料篩選：
  - 依類別（多選，含「全部」選項）
  - 依種類（多選，含「全部」選項）
- 提供帳號關鍵字搜尋。
- 切換排序時需保留目前篩選條件。
- 預設排序採複合鍵：
  1. 類別 ASC
  2. 種類 ASC
  3. 帳號 ASC
  4. 最近更新時間 DESC

### FR-014 類別與種類主檔維護
- 系統需提供「類別主檔」與「種類主檔」於頁面上維護。
- 主檔每筆需包含：
  - `id`
  - `name`
  - `seq`（流水號，系統自動續編）
- 主檔需支援新增、修改、刪除。
- 主檔顯示順序固定為 `seq ASC`。
- 種類必須隸屬於某一類別（`type -> category`）。
- 種類列表需依「類別 -> 種類」層級顯示。
- 維護區塊需可整體摺疊/展開。
- 使用者選取類別主檔項目後，種類維護區僅顯示該類別底下種類。
- 新增種類時，預設直接新增於目前選取類別底下。
- 新增主檔時：
  - 若目前無資料，`seq` 由 `1` 起算。
  - 若已有資料，`seq` 取現有最大值 `+1`。
- 當主檔被帳密資料使用中時，不可刪除該主檔項目。

### FR-009 備註管理
- 每筆資料可編輯備註。
- 備註內容不加遮罩，但隨檔案整體加密。

### FR-010 刪除確認
- 刪除帳號資料時必須二次確認。

### FR-011 表單呈現方式
- 新增/編輯使用彈出對話方塊（Modal）。

### FR-012 向下相容
- 新版系統需可匯入舊版匯出檔（向下相容）。
- 若檔案版本欄位存在差異，需採版本轉換或相容解析策略。

### FR-013 直接覆蓋原匯出檔
- 使用者首次匯入檔案後，系統可保存該檔案控制代碼於記憶體（當前分頁生命週期）。
- 使用者執行「存檔」時，若檔案控制代碼存在且具寫入權限，直接覆蓋原檔。
- 若權限不存在或被撤銷，需提示使用者重新授權，或改用「另存新檔」。
- 此功能以支援 File System Access API 的瀏覽器為主；不支援瀏覽器僅提供下載另存。

  "types": [

    { "id": "uuid", "name": "yahoo.jp", "seq": 2, "categoryId": "<信箱類別id>" },

### 7.2 匯出加密檔案資料模型（落地 JSON）
```json
{
  "formatVersion": "1.1.0",
  "algorithm": {
    "kdf": "PBKDF2",
    "iterations": 100000,
    "keyLengthBytes": 32,
    "cipher": "AES-256-CBC",
    "ivEncoding": "base64",
    "saltEncoding": "base64",
    "cipherTextEncoding": "base64"
  },
  "salt": "<base64>",
  "iv": "<base64>",
  "cipherText": "<base64>",
  "createdAt": "2026-02-24T10:00:00+08:00"
}
```

> 說明：`cipherText` 內容為整包明文 JSON（含 records）加密結果；檔案本身不可出現 records 明文。

## 8. 加密流程規格（對應 crypto-js-lib）

### 8.1 匯出（加密）
1. 使用者輸入 `archivePassword`。
2. 呼叫 `CryptoInitializer.generateSalt(16)` 取得 `bytesSalt/base64Salt`。
3. 呼叫 `CryptoInitializer.deriveKeyFromPassword(archivePassword, bytesSalt, new Pbkdf2Strategy(), 100000, 32)`。
4. 呼叫 `CryptoInitializer.getAesContextForEncryptByRandomIV()` 建立 AES context。
5. 將步驟 3 的 derived key 指派給 AES context 的 `key`。
6. 對明文 JSON 字串呼叫 `encryptWithIVToBase64()` 取得 `cipherText` 與 `iv`。
7. 組合加密檔案 JSON 並下載。

### 8.2 匯入（解密）
1. 讀取加密 JSON 檔案。
2. 驗證 `formatVersion/salt/iv/cipherText` 欄位存在。
3. 將 `salt(base64)` 轉為 bytes。
4. 使用輸入密碼執行相同 PBKDF2 參數派生 key。
5. 呼叫 `CryptoInitializer.getAesContextForDecryptByRandomIV(iv)` 建立解密 context。
6. 指派 derived key 後呼叫 `decryptFromBase64(cipherText)`。
7. 成功則 parse 明文 JSON 並以「覆蓋全部」策略載入；失敗回報錯誤並鎖定重試 5 秒。

### 8.3 安全規則
- 不保存存檔密碼到 LocalStorage。
- 明文 JSON 僅在記憶體短暫存在。
- 匯入後允許將存檔密碼暫存於記憶體直到分頁關閉。
- 解密錯誤訊息避免透露過多細節（不要顯示關鍵內部堆疊）。

## 9. UI/UX 規格

### 9.1 主畫面區塊
1. 工具列：
   - 新增資料
   - 匯入加密檔
  - 存檔
   - 變更存檔密碼
2. 查詢列：
  - 類別篩選（多選下拉，含「全部」）
  - 種類篩選（多選下拉，含「全部」）
   - 帳號關鍵字搜尋
   - 排序方式
3. 主檔維護區：
  - 類別主檔（新增/修改/刪除）
  - 種類主檔（新增/修改/刪除，需指定所屬類別）
  - 顯示層級為「類別底下是種類」
  - 類別與種類皆依流水號排序
  - 支援整體摺疊/展開
  - 選取類別後，種類區顯示該類別底下種類並可直接新增
4. 資料列表：
   - 類別 / 種類 / 帳號 / 密碼歷程 / 備註 / 操作
5. 編輯面板（Modal）：
   - 新增/編輯資料
  - 類別、種類以下拉選單選取
  - 類別選單變更時，種類選單需連動為該類別底下種類
   - 新增密碼歷程（含日期）
   - 編輯備註

### 9.2 密碼顯示規則
- 列表與編輯區中的密碼預設遮罩。
- 每筆密碼旁眼睛按鈕可獨立切換。
- 單筆明文顯示 60 秒後自動恢復遮罩。
- 頁面刷新後回復遮罩預設狀態。

### 9.3 互動流程（精簡）
- 首次進入：新增資料 → 匯出（輸入存檔密碼）
- 再次進入：匯入檔案（輸入密碼）→ 覆蓋載入 → 檢視/編輯 → 可改存檔密碼 → 存檔（優先覆蓋原檔）

## 10. 驗證與錯誤處理

### 10.1 表單驗證
- 類別/種類/帳號不可空白。
- 新增資料時至少一筆密碼。
- 密碼字元不限制（空白字元、特殊字元、Unicode 皆可）。
- 日期格式需可解析（ISO 8601 或 UI 日期元件標準值）。
- 主檔維護時名稱不可空白。
- 主檔維護時流水號由系統自動產生，不需人工輸入。
- 同一主檔（類別或種類）名稱不可重複。

### 10.2 錯誤訊息
- 檔案格式不符：`匯入失敗：檔案格式不正確`。
- 密碼錯誤或解密失敗：`匯入失敗：密碼錯誤或檔案已損毀`。
- 匯入失敗重試限制：`請 5 秒後再試`。
- 匯出失敗：`匯出失敗：請稍後再試`。

## 11. 非功能需求（NFR）
1. 效能：
   - 資料筆數不設定硬上限。
   - 在一般使用情境（至少 1,000 筆 records）下，篩選與排序需保持可用流暢度。
2. 可用性：
   - 常用操作（匯入/匯出/新增）可在 3 次點擊內到達。
   - 最重要驗收焦點為新增、編輯、刪除流程正確。
3. 相容性：
   - 主流現代瀏覽器可運行，不另設最低版本限制。
4. 可維護性：
   - 加密邏輯與 UI 邏輯分層（service + ui）。
5. 可測試性：
   - 至少包含加解密流程、資料排序、篩選條件、CRUD 流程的單元測試。
6. PWA：
   - 提供 Service Worker 與 Web App Manifest，支援離線開啟與安裝。

## 12. 驗收標準（Acceptance Criteria）

### AC-001 新增與顯示
- Given 使用者新增一筆「信箱 / Yahoo平台 / OOOOO」
- When 儲存後顯示列表
- Then 可看到該筆資料且密碼預設為遮罩

### AC-002 編輯與刪除
- Given 使用者已存在一筆資料
- When 進行編輯並儲存，或執行刪除並完成二次確認
- Then 編輯結果正確顯示，且刪除後該筆資料不存在

### AC-003 密碼歷程排序
- Given 同帳號有多筆密碼歷程（含同日不同時分秒）
- When 顯示密碼歷程
- Then 順序為 `changedAt DESC`

### AC-004 匯出加密
- Given 使用者有資料且輸入存檔密碼匯出
- When 開啟匯出的 JSON
- Then 不可直接看到 records 明文內容

### AC-004A 存檔覆蓋原檔
- Given 使用者已匯入某檔案且瀏覽器支援原檔寫入
- When 使用者按下存檔
- Then 系統直接覆蓋該原檔，不另產生新檔

### AC-004B 不支援覆蓋時的回退
- Given 使用者使用不支援原檔寫入的瀏覽器
- When 使用者按下存檔
- Then 系統改以下載方式另存新檔，且功能不中斷

### AC-005 匯入解密與覆蓋策略
- Given 使用者選擇正確檔案並輸入正確密碼，且目前畫面已有資料
- When 匯入
- Then 系統成功還原檔案內容，並覆蓋現有資料

### AC-006 匯入錯誤保護與延遲
- Given 使用者輸入錯誤密碼
- When 匯入
- Then 顯示錯誤、不覆蓋資料，且 5 秒後才可再次嘗試

### AC-007 查詢與排序
- Given 系統中有多種類別/種類與不同帳號
- When 使用者設定多選篩選（可選「全部」）與帳號關鍵字搜尋，再切換排序
- Then 篩選條件保留且結果符合複合排序規則

### AC-008 密碼顯示自動回遮
- Given 使用者點擊眼睛顯示某一筆密碼明文
- When 經過 60 秒
- Then 該筆密碼自動恢復遮罩

### AC-009 向下相容
- Given 使用者匯入舊版匯出檔
- When 檔案格式可識別
- Then 系統可成功解析並載入資料

### AC-010 類別/種類主檔維護
- Given 使用者進入主檔維護區
- When 新增、修改、刪除類別或種類
- Then 資料可正確維護，且列表依 `seq ASC` 顯示

### AC-012 維護區摺疊與類別連動種類
- Given 使用者在主檔維護區
- When 切換摺疊按鈕，或點選某一類別
- Then 維護區可整體摺疊/展開，且種類維護區只顯示該類別底下種類，新增種類會新增在該類別下

### AC-011 新增資料下拉選擇
- Given 類別與種類主檔皆至少存在一筆
- When 使用者開啟新增資料 Modal
- Then 類別與種類需以主檔下拉選單選取，不可自由輸入，且類別選擇後種類需連動

## 13. 實作建議架構
- `EncryptionService`：封裝 `crypto-js-lib` 的加解密、key derivation。
- `FileService`：檔案讀取/下載、JSON 驗證、版本相容處理、原檔覆蓋寫入與權限檢查。
- `PasswordRecordService`：資料新增/編輯/刪除、歷程排序、篩選排序。
- `ImportService`：匯入覆蓋策略、解密失敗重試冷卻（5 秒）。
- `UI State`：遮罩狀態、篩選條件、當前存檔密碼（記憶體）、Modal 狀態。
- `PWAService`：Service Worker 註冊與快取策略。

## 14. 版本相容策略
1. 匯入時先讀取 `formatVersion`。
2. 若為相同主版本（1.x），直接依相容解析器讀取。
3. 若欄位缺漏但可推導，補預設值後載入。
4. 若無法判讀版本，顯示 `匯入失敗：不支援的檔案版本`。

## 15. 決策摘要（由 QA 回填確認）
1. 匯入採覆蓋全部。
2. 刪除需二次確認。
3. 密碼歷程可刪除、不保留刪除紀錄。
4. 存檔密碼不設複雜度與長度限制。
5. 解密失敗需延遲 5 秒才能重試。
6. 匯入後可於記憶體暫存存檔密碼到關閉分頁。
7. PBKDF2 iterations 固定預設 100000。
8. 密碼歷程日期可手動調整，預設為新增當下。
9. 篩選需支援多選，且切換排序需保留篩選。
10. 眼睛按鈕採逐筆切換，60 秒自動回遮。
11. 新增/編輯採 Modal。
12. 匯出檔名採 `password-manage-YYYYMMDD-HHmmss.json`。
13. 不新增多餘 metadata。
14. 需支援向下相容舊版匯出檔。
15. 需具備 PWA 離線能力。
16. 存檔時優先覆蓋原匯出檔；不支援時退回另存新檔。
17. 類別/種類需可在頁面上獨立維護（新增/修改/刪除）。
18. 類別/種類主檔需依流水號排序。
19. 類別/種類流水號由系統自動續編（無資料從 1 開始，否則取最大號 +1）。
20. 新增/編輯資料的類別與種類採下拉選單。
21. 類別/種類篩選需提供「全部」選項。
22. 種類需隸屬類別，且新增/編輯資料時類別與種類下拉需連動。
23. 維護區需可摺疊，且選取類別後種類維護需連動並支援直接新增於該類別。
